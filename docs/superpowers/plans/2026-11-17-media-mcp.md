# media-mcp Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a local-first MCP server that fetches YouTube transcripts (plain text by default), video metadata and media downloads, singly or in batches, structured so new sources, tools and transports are additions.

**Architecture:** A pnpm workspace with `packages/core` (domain, Provider port, yt-dlp adapter, services, infra, no MCP imports) and `apps/server` (the only package importing the MCP SDK, building tools from a registry, with a stdio entry). All yt-dlp access goes through the Provider port and a process runner that never uses a shell.

**Tech Stack:** TypeScript strict (ESM, Node 22+), `@modelcontextprotocol/sdk` 1.32.2, zod 4.6.7, execa 10.2.1, p-limit 7.3.3, tsdown 0.23.7, Vitest 5.1.0, Biome 2.6.8, knip 6.45.1, TypeScript 7.0.2 (versions looked up on 2026-11-17 and pinned through the pnpm catalog), yt-dlp 2026.10.26 via Homebrew.

**Spec:** `docs/superpowers/specs/2026-11-17-media-mcp-design.md`

## Global Constraints

- Node 22 or newer, ESM only, pnpm only (never npm or yarn).
- yt-dlp is the single extraction engine, installed with Homebrew. It needs an external JavaScript runtime for YouTube, and Node or Bun satisfies this. ffmpeg is required for merging streams and is already installed.
- TypeScript strict with no `any`, functional style with immutability and early returns, functions of 20 lines or fewer, named constants, validation at boundaries only, zero comments unless the reason is non-obvious.
- No commits until the owner asks. Run `git init` once in Task 1 and never commit, so every "checkpoint" step below means running `pnpm check`, not committing.
- Nothing may write to stdout except MCP protocol frames in the stdio entry. Logging goes to stderr.
- Child processes use `execFile`-style argument arrays, never a shell, and a `--` separator precedes every URL.
- Defaults from the spec: language `en`, timestamps off, transcript and info playlist cap 50, download cap 10, concurrency 4.

## Review Focus

Inputs and conditions the spec implies but does not enumerate, each pinned by a test in the owning task.

1. A URL that looks like a yt-dlp option (`--exec=touch /tmp/x`, `-o /etc/x`) must yield `INVALID_URL` and never start a process (Task 5, Task 6).
2. The same video submitted in different forms (`watch?v=`, `youtu.be/`, `shorts/`, or with `&t=` and `&list=` extras) must be fetched once and reported once (Task 5, Task 8).
3. A video with no captions in the requested language must produce a `NO_CAPTIONS` entry listing the languages that exist, while the rest of the batch still succeeds (Task 6, Task 8).
4. An `outputDir` such as `../../etc` or a symlink pointing outside the output root must yield `OUTPUT_PATH_ESCAPE` (Task 4, Task 7).
5. A missing or outdated yt-dlp must surface as `TOOL_MISSING` or `TOOL_OUTDATED` with the install command, and not as a generic process failure (Task 3, Task 6).
